# 短剧故事结构

## 目标

把一个题材、灵感或大纲转成适合短剧生产的故事骨架。

## 项目卡模板

- 剧名：暂定名即可。
- 类型：明确主赛道和副类型。
- 核心受众：谁会被情绪击中。
- 一句话钩子：谁 + 困境 + 反转。
- 主角欲望：主角最想得到什么。
- 主角困境：阻止主角的现实压力。
- 对手系统：人、制度、秘密、误会、阶层差。
- 情绪承诺：爽、甜、虐、燃、悬疑、治愈。
- 视觉承诺：城市夜景、豪门别墅、职场会议室、校园、古风院落等。

## 爆款短剧常用结构

### 逆袭结构

1. 主角被轻视或羞辱。
2. 主角隐藏身份、能力或资源。
3. 对手持续加码压迫。
4. 主角小反击，观众获得即时爽感。
5. 更大身份或真相延后揭露。

### 复仇结构

1. 旧伤或冤案开场。
2. 主角伪装进入敌方系统。
3. 每几集拿下一枚证据。
4. 对手发现异常并反扑。
5. 终局公开真相并完成审判。

### 甜宠结构

1. 两人因误会、契约或危机绑定。
2. 外部压力制造亲密接触。
3. 一方先动心但不承认。
4. 误会爆发，关系跌入低谷。
5. 公开选择，完成情感确认。

### 悬疑结构

1. 用异常事件开场。
2. 每集给一个线索，同时制造新问题。
3. 线索互相矛盾。
4. 中段出现错误答案。
5. 终局用关键证据重排因果。

## 分集节奏

短剧每集最好只解决一个核心问题，同时提出一个更大的问题。

- 第 1 集：强钩子 + 主角困境 + 结尾反转。
- 第 2-3 集：关系绑定 + 对手压迫 + 小胜利。
- 第 4-6 集：秘密露出 + 情绪升级 + 付费点。
- 中段：胜负反复，主角付出代价。
- 后段：身份、证据、感情、权力集中爆发。
- 终局：公开真相，完成情绪兑现。

## 结尾钩子类型

- 身份揭露：他竟然是……
- 证据反转：手机里出现关键录音。
- 危险逼近：门外传来脚步声。
- 情感选择：主角必须在爱与复仇之间选择。
- 权力翻盘：被羞辱者掌握全局。
- 误会扩大：关键人物听到半句话。

## 输出要求

当用户只给一个题材时，先输出：项目卡、主角/对手、前 5 集梗概、核心钩子表。不要直接写完整长剧本，除非用户明确要求。

## 数据中心写回硬规则

故事结构阶段不是自由讨论阶段，必须把可被下游继承的字段写入 `短剧生产数据中心 — [项目名]`。不得只在聊天正文中给出故事设定而不写入数据中心。

必须写回：

- `project_name`
- `project_type`
- `output_ratio`
- `output_duration_plan`：按平台节奏估算单集 / 总时长，不把 2 分钟写死为固定值；参考红果短剧、优酷视频、腾讯视频、爱奇艺视频的核心节奏，计算后可叠加剪辑余量 / 安全缓冲，但最终单集总时长不得超过 3 分钟。
- `original_request`
- `script_source`
- `reference_assets`
- `user_constraints`
- `auto_inferred_context`
- 故事主线、主冲突、核心钩子、受众、视觉承诺
- 主要角色候选及其初始功能
- 前 3-5 集或用户要求集数的剧情范围

若用户只给灵感，允许 agent 补全故事骨架，但必须把所有自动推断写入 `auto_inferred_context`，并标明依据。不得把自动推断伪装成用户原始设定。

## 下游继承硬规则

进入剧本阶段前，必须确认故事阶段至少提供：

```text
story_source_id: <稳定编号>
project_name: <项目名>
main_conflict: <主冲突>
main_characters: [角色名]
visual_promise: <视觉承诺>
episode_ranges: [集数/段落范围]
stage_status.story: PASS
```

如果缺少项目名、主角、主冲突、视觉承诺或集数范围，不得进入剧本阶段；必须先补齐故事数据中心。
