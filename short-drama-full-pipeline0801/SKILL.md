# Short Drama Full Pipeline

## 核心原则

使用本 Skill 时，始终把目标定义为“可生产的短剧项目”，而不是单独写一段故事。每一步都要服务于下游生成：人物能被画出来，场景能被复用，镜头能被拍出来，提示词能被视频模型执行，最终能进入剪辑合成。

不得逐字复刻任何外部或内部链路文本。本 Skill 是原创的短剧生产标准，后续若用户要求“与 short-drama-full-pipeline 100% 相同”，以本文件和本目录下 references 的当前内容为唯一标准。


## 全链路最高优先级规则索引（防执行不完全 / 防旧规则回退）

本节只做规则索引与冲突裁决，不压缩、不删除、不替代下方任何生产能力。若旧段落、旧模板、历史摘要、缓存记忆或其它 Skill 与本节指向的 v3 / v4 / v5 / 全链路完整扩容规则冲突，一律以本地当前文件和最新 reference 为准。旧规则只可作为内部历史参考，不得覆盖最新补丁。

1. 本地链路锁最高优先级：production_chain_id、production_chain_name、workflow_source、fallback_allowed 必须贯穿全链路。
2. 不压缩最高优先级：资产、分镜、关键帧、视频、声音、后期、QC 任务包必须逐项完整展开，禁止“同上 / 按前文 / 继承上版 / 完整继承某资产 / 参考前面”。
3. 视频 v3 / v4 最高优先级：固定顺序、[要求] 场景机位前缀、[画面] 双模式固定块、15 秒拆分、天气光线、@引用、每镜三句音色、条件化辅助图禁令、唯一人物禁令、@角色情绪说、每镜备注、读音替换映射必须齐全。
4. 资产 v5 最高优先级：后续角色变体可引用 source_identity_asset_ref，但仍必须完整重写身份锚点、三庭五眼、体型气质、服装锚点、状态变化、时代朝代职位锁、连续性禁令和负面提示。
5. 时代 / 职务 / 制式锁最高优先级：历史时期、朝代、年代、地域制度、职位、职务、官阶、服饰制度、器物制度、建筑制度必须写入生产数据中心，并被资产提示词消费。
6. 共享道具锚点最高优先级：同一道具在角色资产、单独道具资产、视频提示词中必须使用同一 shared_prop_visual_anchor，核心外观描述逐字一致。
7. 景别优先级最高优先级：Skill 的景别规则高于剧本视觉备注；默认优先大特写、特写、近景、中景、前景对焦 + 背景高虚化；远景 / 全景 / 大远景必须有 strong_story_need。
8. FAIL 路由最高优先级：任何 FAIL_* 不得被忽略或口头绕过；必须按 qc-checklist.md 的“统一失败路由矩阵”回到最近 producer 阶段修复。

## 本地链路锁

当用户要求使用本地 `short-drama-full-pipeline` / “神笔制作”链路，或表达“不要走线上通用制作链路”“锁定我的本地 skill”“不得 fallback 到其它链路”等同义意思时，必须锁定：

```text
production_chain_id: short-drama-full-pipeline
production_chain_name: 神笔制作
workflow_source: user_skill_locked
fallback_allowed: false
local_skill_root: from os.path import expanduser
target_path = expanduser("~/Movies/Hub/skills/short-drama-full-pipeline")
```

锁定后，每次制作任何产物前必须重读本地 `SKILL.md` 与当前阶段对应的本地 reference 文件，并在内部确认 `template_source`。禁止改走线上通用制作链路、其它 Skill 主模板、旧缓存或 light dispatch。涉及视频提示词、VIDEO_DISPATCH_PACKAGE、派单前冻结与表现层提示词时，必须额外真实读取 `references/video-prompt-pipeline.md` ，不得只靠历史摘要继续。链路锁、断点审计与引用审计规则见 `references/chain-audit.md`。

## 启动弹窗：写实真人模式 vs 3D 动画 CG 模式（强制）

用户进入“神笔制作”链路、还没有生成任何角色资产之前，**必须**先用弹窗询问用户选择视觉模式，二选一进入不同制作链路分支：

| 模式 | 含义 | 角色资产派单提示词来源 | 视频提示词与最终成片效果 |
|---|---|---|---|
| A. 写实真人风格（推荐） | 走原写实真人电影风格，沿用历史资产提示词骨架 | `asset-pipeline.md` §“写实真人角色资产派单” | 超写实真人电影质感剧情视频 |
| B. 3D 动画 CG 风格 | 走国漫顶级 3D 动画 CG 电影质感，使用 `references/animation-character-converter.md` 中的转换模版 | `asset-pipeline.md` §“3D 动画 CG 角色资产派单” + `references/animation-character-converter.md` | 国漫顶级 3D 动画 CG 电影质感剧情视频 |

### 选模式时的强制约束

1. 必须用 `question` 工具一次问完，不得拆分。
2. 一旦选定，整条链路（角色 / 场景 / 道具资产、视频提示词、QC、后期）都必须保持同一模式，不得中途混用。
3. 如果用户授权词 = `随便 / 都行 / 你看着办` 或对话已确定模式，直接按该模式走，不再追问。
4. 如果用户没明确授权但已经提供“真人版本”或“动画版本”等描述词，按描述词锁定；描述词冲突时退回弹窗。
5. 任何资产的派单提示词第一行必须显式声明 `production_visual_mode: cinematic_realistic | top_chinese_3d_animation_cg`，与启动弹窗选择一致。

## 提示词语言硬规则（全链路强制中文）

1. 神笔制作中的角色资产、场景资产、道具资产、分镜、关键帧、视频提示词、VIDEO_DISPATCH_PACKAGE、沙盒测试提示词文档，**所有可见提示词正文默认必须使用中文**。
2. 禁止为了“模型更好理解”把资产提示词或视频提示词主体写成英文；不得先写英文稿再翻译；不得输出中英并列的提示词正文。
3. 用户可见文档实行“极限全中文”：沙盒文档、资产提示词文档、视频提示词文档、任务包展示层、审阅层中的字段名、段落标题、描述正文、负面提示都必须中文化；不得出现英文提示词正文或英文禁止词列表。
4. 唯一允许在用户可见文档中保留的非中文内容：模型名（如 image2）、项目链路 ID、文件路径、必要编号、版本号、用户明确要求保留的非中文台词或入画文字。真正派单接口内部所需的英文参数、枚举值、机器 token 只能放在“内部派单映射层”，不得混入用户可见提示词正文。
5. 若剧本台词中明确标注非中文台词，台词原文必须逐字保留；但台词之外的动作、表演、镜头、光影、参考图说明、负面提示仍必须使用中文。
6. 历史模板中出现的 `front view`、`side view`、`Negative Prompt`、`Native audio`、`Original request`、`cinematic` 等英文结构词，正式输出时必须改写为中文等价词，例如“正面视图”“侧面视图”“负面提示”“原生音频”“原始需求”“电影质感”。仅内部派单映射层可保留机器字段。
7. 沙盒测试模式同样适用本规则：不真实制作资产或视频时，画布上的完整提示词文档也必须是中文提示词。

## award-winning-performance-prompt-v1-1融合与全量前置快照机制

本 Skill 内部融合“award-winning-performance-prompt-v1-1”的中文片段镜号格式、Seedance 2.0 多模态提示词规则与角色音色参考规则。涉及视频提示词、角色音色、表演层、镜号格式、全量前置快照或声音 owner 时，必须读取 `references/actor-performance-voice-integration.md`，不得只依赖外部 Skill 触发。

进入剧本标准化后、资产阶段前，必须建立 `full_preproduction_snapshot`。该快照允许全量前置本次制作所需的原始数据、决策字段、角色造型变体、场景状态变体、音色计划、声音 owner、参考资产计划、表演草案与镜号草案。后续若角色资产图、场景方向、道具参考、音色来源、audio_owner、镜头时长、角色造型变体或场景状态变体发生变化，不得直接覆盖旧快照，必须新增 `preproduction_patch`，并生成 `current_active_snapshot_resolved` 合成版。下游资产、分镜、视频提示词和 QC 只允许消费合成版。

视频提示词阶段默认使用中文片段镜号格式。若角色预计出现在 ≥2 段视频，必须通过生产数据中心的视频任务映射统计启用角色音色参考。首次缺少音色参考时，弹窗提供：A 首段视频后提取音色（推荐）、B 上传角色音频、C 后期配音 / speech 缺口保留。当前默认优先视频生成时由 Seedance 原生音频按角色音色说逐字台词。

## 角色造型变体与场景状态变体前置计算

剧本标准化后必须立刻计算：

- `character_look_variant_plan`：按剧情场景更换、天气、季节、日夜、身份状态、伤损、妆造、妆感、发型、发饰、年龄变化、武器、贴身道具，以及角色是否有现实时间换装，逻辑计算同一角色需要几套人物资产图。
- `scene_state_variant_plan`：同一场景只要出现季节、天气、日/夜、场景受损、场景内新增固定道具、剧情状态或光源状态变化，就必须计算并生成对应场景状态资产图。

这两类变体必须纳入 `full_preproduction_snapshot`，后续变化通过 `preproduction_patch` 更新。没有变体计划或合成版未通过 QC，不得进入资产阶段。

## 场景资产方向锁定（统一规则，两模式共用）

- 不再生成场景六视图 / 六分区合成图。
- 每个场景资产按“镜头需要的视角方向”单独出一张：正面、反向、左侧、右侧、俯视 / 鸟瞰、关键机位光影。是否生成某个方向由下游视频提示词决定。
- 视频提示词中的所有镜头机位 / 调度必须遵循“以当前场景资产视角方向为背景机位”：
  - 使用正面场景资产 → 全部镜头必须以正面为背景机位（正面机位、过肩正面、浅景深前景实背景虚等）
  - 使用反向场景资产 → 全部镜头必须以反向为背景机位
  - 使用左侧场景资产 → 全部镜头必须以左侧为背景机位
  - 其它方向同理
- 场景资产的视角方向从生产数据中心 `scene_view_orientation` 字段读取，源头是剧本场次 + 视频任务规划的镜头方向；agent 不得临场修改视角方向。
- 角色 / 道具在场景中的左右、前后、朝向关系与场景资产视角方向必须自洽，不得漂移。

## 道具资产使用次数判定（统一规则，两模式共用）

- 道具是否生成资产图，先判定该道具在本次制作的所有视频任务中出现次数：
  - 出现 ≥2 次 → 必须生成道具资产图
  - 出现 1 次 + 需要书写 / 文字 / 符号 / 图样 / 印章 / 数字等视频模型容易出错的元素 → 必须生成道具资产图
  - 出现 1 次 + 不需要书写 / 文字 / 符号 / 图样 / 印章 / 数字 → 可不生成道具资产图，但必须在生产数据中心登记 `prop_asset_status: skipped_single_use_no_text`
- 若道具需要非常准确的动画效果（数字变化、乱码变化、印章盖印、字迹浮现、纸条展开等），必须用弹窗提醒用户：
  - 用户必须在视频派单前提供一段描述清楚的参考视频
  - 参考视频命名规则：`道具动效参考-<prop_id>-<道具名>.mp4`
  - agent 必须记住该命名，并在制作该道具出现的视频提示词时引用并说明“本视频用于生成该道具的动画效果参考”
  - 同时在生产数据中心登记：`prop_animation_reference: <path> + prop_animation_description: <简单描述>`
- 道具资产不再使用九宫格 / 自动网格 / 多道具合并图，每个道具独立一张图。

## 舞台定位图与黑白分镜图（统一规则，两模式共用）

- 舞台定位图与黑白分镜图**默认不推荐生成**，进入分镜阶段前必须用弹窗询问用户：
  - 是否生成舞台定位图（不推荐） → 若生成，需消费场景资产的视角方向（与上文“场景资产方向锁定”一致）
  - 是否生成黑白分镜图（不推荐） → 若生成，需写明视频提示词将额外继承黑白分镜图作为参考图
- 即便生成舞台定位图 / 黑白分镜图，最终视频画面也不得出现坐标网格、色块、箭头、形状编码、文字标注、框线、UI、黑白线稿、白底、草图线条或分镜质感。
- 视频提示词中的 `100×100 xy 坐标描述`必须用**纯自然语言**方式书写，例如“角色位于舞台左侧 30% / 桌案位于画面中央偏前 / 入口在画面右后 / 角色 A 视线指向入口方向 / 角色 B 从入口走向角色 A”，不得使用数字 `15,30` 这种纯坐标格式，更不得写 `[15,30]`；色框、色块、箭头全部不再出现在视频提示词中。
- 黑白分镜数据只作为内部数据继承并融合进视频提示词的逐秒段落，不得在最终 prompt 中单独写成说明段。

## image2 资产派单参数（分类型，两模式共用）

| 资产类型 | 模型 | 画质 | 清晰度 | 比例 |
|---|---|---|---|---|
| 角色资产 | image2 | 高 | 2K | 16:9 |
| 场景资产 | image2 | 高 | 2K | 16:9 |
| 道具资产 | image2 | 高 | 2K | 16:9 |

高清增强策略：资产基础生成统一使用“画质：高、清晰度：2K、比例：16:9”。资产图生成后，若当前运行环境或画布提供“高清增强 / 分辨率提升 / upscale”功能，必须自动执行高清增强至 4K，并把增强后路径写回资产池；若当前 agent 无法调用该功能，必须明确提示用户在画布中对对应资产执行高清增强至 4K，不得假装已经增强完成。

如果实际派单工具需要 canonical model id，可在派单层把 `image2` 映射为当前系统可用的对应图像模型，但资产阶段文档和用户可见规格必须保留 `模型：image2` 的写法。

## 快速路由

根据用户输入选择入口：

0. 用户要求锁定本地链路、继续制作、验收并继续、避免线上通用链路：先检查项目目录是否存在 breakpoint.json，存在则读取定位当前阶段与中断点；再读 references/chain-audit.md，最后按当前阶段读取对应 reference。
1. 只有灵感或题材：先读 `references/story-structure.md`，产出项目定位、主冲突、人物关系、前 3 集方向。
2. 已有大纲或剧本：先读 `references/script-format.md`，规范成场次、对白、动作和节拍。
3. 要做分镜或视频：读 `references/storyboard-pipeline.md` 与 `references/video-prompt-pipeline.md`，先分镜后提示词。
4. 要做角色/场景/道具资产：读 `references/asset-pipeline.md`，先拆资产再派图像任务。若选择 3D 动画 CG 模式，必须额外读 `references/animation-character-converter.md`。
5. 要全自动推进：依次读全部 reference，按“故事 → 剧本 → 资产 → 分镜 → 视频 → 后期 → QC”执行。
6. 要做声音、剪辑或成片：读 `references/post-production-pipeline.md`，明确音频 owner、剪辑顺序和混音规则。
7. 用户要求检查、返工、补齐：读 `references/qc-checklist.md`，按缺口清单逐项修正。

## 标准生产链路

### 阶段 0：生产数据中心与链路审计

进入正式制作前，建立或更新 `短剧生产数据中心 — [项目名]`，用于登记剧本源信息、对白原文、视频任务、资产池、空间/分镜映射、提示词映射、阶段状态和 `production_visual_mode`。规则见 `references/production-data-center.md`。

如果项目处于本地链路锁定状态，每个阶段开始前都必须执行 `LOCAL_CHAIN_AUDIT`：确认已读取本地 `SKILL.md`、当前阶段 `template_source`、上游输入、预期输出、参考路径清单和断点状态。任何数据断点、参考图引用断点或提示词引用断点都必须先修复再继续。

维护或加硬本 Skill 时，默认只能追加、细化、加硬规则；不得以“优化”“压缩”“去重”“更适合模型”等理由删减用户已确认的本地链路锁、数据中心、对白保真、参考图继承、提示词映射、QC 验收或禁止 fallback 规则。

### 阶段 1：项目定位

输出短剧项目卡：

- 类型：都市、逆袭、复仇、甜宠、悬疑、穿越、重生、豪门、家庭、职场、古装、玄幻等。
- 受众：核心观看人群、情绪需求、爽点类型。
- 一句话钩子：15 字以内说明“谁在什么困境里如何反转”。
- 主冲突：角色欲望、阻力、代价。
- 付费点：每 3-5 集一次强悬念或强反转。
- 视觉基调：写实、电影感、动态漫、国风、暗黑、甜宠明亮等；并明确 `production_visual_mode: cinematic_realistic | top_chinese_3d_animation_cg`。
- 单集时长：按平台节奏估算，参考红果短剧、优酷视频、腾讯视频、爱奇艺视频的核心节奏，硬上限以 3 分钟为准；输出计划时要预留剪辑余量 / 安全缓冲，但最终单集总时长不得超过 3 分钟，不能把 2 分钟写死为固定值。

### 阶段 2：人物系统

每个主要角色必须有：

每个被下游引用的角色都必须有完整身份结构；“主要角色”只代表叙事优先级，不代表身份字段可简化。只要角色拥有 `character_id`、进入角色资产、出现在分镜 / 视频提示词、或在多角色框选参考图中作为独立颜色框被引用，均必须按同一标准写入：

- 角色名与功能：主角、对手、盟友、情感对象、催化者、群像框选人物等。
- 外在识别：年龄段、气质、发型、服装、标志物。
- 三庭五眼：主要所有被下游引用的角色必须把面部身份结构写成可继承字段，剧本未明写时按人物人设合理补齐，并进入生产数据中心和资产链路；不得主角详细、配角或群像简略。
- 身份别名与共体锁：改名、伪装、双魂共体、同一身体不同掌控状态必须登记 `character_name_aliases` 与 `canonical_identity_label`；例如“角色A / 角色B共用身体 / 角色C”必须指向同一身体身份主键，只允许表演状态和剧情称呼变化，不得生成互相冲突的脸。
- 内在驱动：欲望、恐惧、秘密、底线。
- 关系钩子：与主角的利益冲突或情感债。
- 视觉连续性提示：后续所有图像/视频任务都要复用。

### 阶段 3：分集与剧本

先做分集节拍，再写剧本。短剧每集必须包含：

- 开场钩子：3 秒内让观众知道冲突。
- 中段升级：误会、压迫、证据、威胁、情绪爆点。
- 结尾钩子：反转、身份揭露、危险逼近、选择困境。

剧本输出采用：场次编号、场景、时间、人物、动作、对白、情绪、镜头备注。

每次由本 Skill 优化、改写或新写的剧本，都必须同步写入或更新生产数据中心；不得只在聊天中交付剧本文本而不登记 `scene_id`、`dialogue_id`、`required_characters`、`required_scene`、`required_props`、`face_structure_3t5e`、视频任务映射和阶段状态。对白标准化阶段不得擅自删除、缩减、概括或简化原剧本台词；除非存在错别字、明显病句、标点缺失或其他会导致台词明显错误的情况，才允许做最小纠错，其余情况必须逐字保留。

### 阶段 4：资产拆解

按启动弹窗选定的 `production_visual_mode` 决定角色资产派单骨架（写实真人 → `asset-pipeline.md` §“写实真人角色资产派单”；3D 动画 CG → `asset-pipeline.md` §“3D 动画 CG 角色资产派单” + `references/animation-character-converter.md`）。场景与道具资产规则两模式共用。

从剧本中抽取：

- 角色资产：主角、反派、配角、群众、群像框选人物；凡被下游引用或独立颜色框标记的人物都按角色资产处理。
- 角色三庭五眼字段：从剧本 / 人物设定 / 生产数据中心继承到资产需求包和角色资产提示词，不得临场跳过；所有被下游引用的角色使用同一字段深度，不得主角详细、配角简略。
- 角色提示词继承字段：每个角色资产提示词必须继承 character_name_aliases、canonical_identity_label、identity_anchor、face_structure_3t5e、costume_anchor、state_variants、source_scene_ids、source_dialogue_ids、used_by_video_tasks；缺任一项不得进入下游。
- 资产提示词完整合同：每个需要生成的角色、场景、道具都必须输出一段可复制、可独立派单的完整提示词块，不得只写表格行，不得只写“同上 / 参考前文 / 按首个角色 / 继承上文”。后续任一角色、场景或道具的字段数量、段落结构、风格锁展开、负面提示、连续性禁令和细节密度不得低于第一个资产。若发现首个资产完整、后续资产简化，必须标记为 `FAIL_ASSET_PROMPT_COMPLETENESS_MATRIX` 并回到资产提示词阶段重写。
- 全链路完整扩容：资产提示词、分镜任务、关键帧任务、视频任务包、声音任务包、后期任务包都必须独立成块展开当前任务所需信息；不得用“同上”“按前面”“参考上文”承接关键字段；不得为了节省篇幅压缩后续任务。
- 场景资产：固定主场景、一次性场景、关键转折场景；不再生成场景六视图合成图。按下游视频提示词的镜头机位方向生成对应方向的场景资产图（正面 / 反向 / 左 / 右 / 俯视 / 关键机位光影），方向锁定由 `scene_view_orientation` 字段控制；所有镜头必须遵循“以场景资产视角方向为背景机位”。
- 道具资产：按道具使用次数判定（≥2 次或带文字/符号/数字 → 必须生成；否则可不生成）。不再生成多道具九宫格 / 自动网格图，每个道具独立一张图。若道具需要准确动效，必须用弹窗提示用户提供参考视频并按命名规则登记。
- 状态变化：妆发、服装、伤痕、血迹、泥灰、破损、情绪递进。

资产要标明“是否需要参考图”“是否跨集复用”“是否影响剧情”。

### 阶段 5：舞台定位与分镜

舞台定位图与黑白分镜图默认不推荐生成，进入分镜阶段前必须用弹窗询问用户。

多人场景先锁定空间关系，再写镜头。每个镜头记录：

- 镜头编号、时长、景别、机位、运镜。
- 画面主体、动作、表情、空间位置。
- 台词或声音内容。
- 需要的角色/场景/道具参考图。
- 与上一镜头的衔接方式。
- 必须遵循“场景资产视角方向 = 背景机位”的方向锁定。

### 阶段 6：关键帧与视频提示词

先生成稳定关键帧，再写视频提示词。每个视频提示词必须包含：

- 模型、比例、时长。
- 首帧/参考图路径。
- 角色身份锁定。
- 场景与动作（场景资产视角方向必须与镜头背景机位一致）。
- 镜头运动。
- 表演细节。
- 声音归属：原生音频、独立配音、独立 BGM 三者不要重复。
- 文件命名：所有生成的图片、视频与关键中间产物，初始文件名必须使用中文精简命名，避免长串英文、无语义编号或临时代号；生成时就命名好，不要依赖后续改名。

禁止在视频链路里主动加字幕；如用户要求字幕，建议后期软件添加。

### 阶段 7：声音与后期

声音分工：

- 台词/旁白：speech 或视频模型原生音频，二选一。
- BGM/歌曲：music，只生成一次主 BGM，不按片段重复生成。
- 合成、混音、拼接、口型同步：editing。

成片前检查节奏、响度、对白清晰度、镜头连续性。

### 阶段 8：质量控制

交付前必须检查：

- 主角身份是否跨镜一致。
- 所有被下游引用的角色身份是否跨镜一致，且是否都具备完整 `face_structure_3t5e`、`character_name_aliases` 与 `canonical_identity_label`；不得只检查主角。
- 服装、发型、道具是否连续。
- 场景空间是否跳变；所有镜头机位 / 调度是否遵循场景资产视角方向。
- 剧情因果是否清楚。
- 每集结尾是否有钩子。
- 视频提示词是否可直接执行。
- 是否存在重复生成同一类声音的问题。
- 角色资产是否与 `production_visual_mode` 一致（写实真人 vs 3D 动画 CG）；3D 动画 CG 模式下，角色资产是否被 `references/animation-character-converter.md` 的转换模版处理过、是否含真人风险词。
- 道具资产是否按使用次数判定（≥2 次或带文字/符号/数字 → 必须生成；否则可不生成）；需要动效参考视频的道具是否已登记 `prop_animation_reference` + `prop_animation_description`。
- VIDEO_DISPATCH_PACKAGE 必填字段是否完整且与上游数据中心一致（详见阶段 9 字段清单）。

### 阶段 9：VIDEO_DISPATCH_PACKAGE 与视频提示词展示

进入最终视频提示词展示与派单前，必须把 VIDEO_DISPATCH_PACKAGE 完整冻结为可执行任务包，并按当前视频任务真实读取 `references/video-prompt-pipeline.md`；若涉及派单前检查、返工、恢复或引用核对，还必须同步读取 `references/chain-audit.md`、`references/production-data-center.md` 与 `references/qc-checklist.md`。本阶段不得只靠上文摘要，不得把历史聊天内容当作当前 prompt 的唯一依据。

本阶段必须展示并写回：

- `prompt_id`、`video_task_id`、`shot_id` 或 `panel_id`
- `reference_image_paths_expected` 与 `reference_image_paths_actual`
- `reference_usage_statement_actual`
- `audio_owner`、`verbatim_lock`、`status`
- `cross_video_continuity_ref`
- `stage_map_coordinate_data_actual`（仅含 100×100 自然语言描述）
- `storyboard_order_composition_action_data_actual`
- `verbatim_dialogues`
- 参考图用途、引用边界、禁止继承字段

舞台定位图 / 黑白分镜图若用户明确授权生成，可作为 `reference_image_paths_actual` 一部分，但最终视频画面不得出现坐标网格、色块、箭头、形状编码、文字标注、框线、UI、黑白线稿、白底、草图线条或分镜质感。默认不生成、不传入。

## 视频提示词模板、摄影描述与时长科学计算硬规则（强制补丁）

本节为视频提示词阶段最高优先级补丁。涉及视频提示词、VIDEO_DISPATCH_PACKAGE、沙盒提示词、摄影方案、表演推导、镜号拆分、时长估算时，必须读取并消费 references/video-prompt-pipeline.md、references/actor-performance-voice-integration.md、references/cinematography-profiles.md 与 references/qc-checklist.md。

1. 用户可见视频提示词固定顺序：开场行 → [电影质感] → [画面美学风格] → [环境光影] → [人物站位] → [内容概述] → [情绪氛围] → [衔接参考首帧] → [参考素材] → [要求] → 镜号行 → [画面] → [片段结尾] → 台词保真禁令 → [禁令]。其中 [电影质感] 必须紧跟开场行，作为模型风格锚定第一段。
2. cinematography-profiles.md 可保留摄影机、镜头、24fps、180度快门、EI 等专业审计参数；但最终用户可见提示词与派发提示词必须使用视觉描述层。3D 动画 CG 模式把 24fps / 180度快门等转换为“自然电影感运动模糊”，把空间压迫转换为“窄空间近景构图，营造压迫感”，并把“人物剧情片电影质感 / 类型片电影质感”放在 [电影质感] 第一句。写实真人模式可保留摄影机与镜头型号，但必须中文化为画面效果描述，例如“ARRI Alexa Mini LF 摄影机质感，库克镜头暖调柔和高光光晕，50mm 定焦 f/2.8，3200K 暖色温，电影级景深，柔和焦外虚化，自然镜头呼吸感，弱光戏剧化对比”。
3. FACS / BACS / RACS 只作为 Skill 内部表演计算体系与任务包审计字段存在。用户看到的提示词、prompt_chinese_dispatch、真实派发 prompt、沙盒提示词正文中禁止直接出现 FACS / BACS / RACS / AU 编码，必须转换为自然语言，例如“眼睑平稳、眉头舒展、肩颈自然下沉、胸腹起伏微弱平缓”。
4. 时间段不得只写单字“夜”，必须使用凌晨、清晨、早晨、中午、下午、傍晚、夜晚、深夜等高权重词，并结合天气 / 光线写成“夜晚 / 室外小雨窗外雨景”“下午 / 窗外阴天室内柔和天光”等。
5. 所有 VO 写为“画外音（VO）”，所有 OS 写为“内心独白（OS）”。
6. [参考素材] 与 reference_image_paths_actual 只包含当前镜号实际出现、触碰、读屏或使用的素材；镜号未提及的道具不得生成、不得传入。
7. 视频时长不得先固定 10-15 秒再硬塞台词。必须按台词字数与语速、画外音（VO）/内心独白（OS）/角色对白、表演留白、空镜、道具读屏、动作复杂度、摄影方案节奏系数计算 duration_calculation，再决定总秒数与镜号数量。若计算后超过模型舒适时长，必须拆分 video_task_id，不得删台词、加速朗读或牺牲表演。


## 视频提示词 v3 防漏字段与 15 秒硬上限（最高优先级补丁）

本节优先级高于旧视频提示词规则。每个最终视频提示词必须在 [要求] 中逐字写入：严格遵守180度轴线与视线匹配原则，严防越轴跳切。画面干净又高级；画面里前中远景递进关系分明。极具影视写实感与物理细节真实感。

每个最终视频提示词必须写 [画面] 固定块。写实真人模式使用：无水印，无字幕，无logo，无背景音乐。电影级光影，8K写实，人物皮肤纹理清晰，面部微表情舒展克制，无夸张神态；体态端正放松，肢体无僵直感；步态平稳协调；搭配眨眼、轻呼吸、手指微动等低幅度无意识小动作，真实肢体动作，电影质感，专业影视摄影。3D 动画 CG 模式使用等价块：无水印，无字幕，无logo，无背景音乐。电影级光影，8K级精细CG渲染，CG角色材质细节清晰，陶瓷化SSS皮肤shader干净通透，无真实皮肤纹理，面部微表情舒展克制，无夸张神态；体态端正放松，肢体无僵直感；步态平稳协调；搭配眨眼、轻呼吸、手指微动等低幅度无意识小动作，真实肢体动作，电影质感，专业影视摄影。

当前模型单段视频硬上限 model_duration_cap_seconds: 15。任何计算时长超过15秒的视频任务必须拆分为多个 video_task_id，每段不超过15秒；禁止删减台词、提高语速或压缩表演留白。

每个 video_task_id 必须有 weather_light_context，并在 [环境光影] 与镜号场次中落地。只写“夜晚 / 江家客厅 / 室内暖光”不合格，必须写外部天气或光线来源，如“夜晚 / 窗外小雨室内暖光”。

只要最终画面描述中提及人物、场景、道具且该对象可见、被触碰、被读屏、作为证据点或空间背景使用，就必须 @引用；画外音（VO）、内心独白（OS）和逐字台词内部出现的名称例外。

每个镜号内某角色首次画外音（VO）、内心独白（OS）或说台词前，必须写不少于3句完整音色描述句，覆盖音高/厚薄、气息/共鸣、语速/情绪控制三个维度；跨镜号必须重新写，禁止“同上”。

舞台定位图和黑白分镜图禁令必须条件化：用户未启用时，不得写舞台坐标网格、色块、箭头、黑白分镜质感、草图线条、分镜边框或白底分镜背景等禁令；只有启用对应辅助图时才写。

视频任务不得首段完整后续压缩。每个 video_task_id 必须独立完整展开全部字段，不得用“同上、按前文、延续上段、参考前面”承接关键提示词。


## 视频提示词 v4 场景机位、台词、备注与读音修正（最高优先级补丁）

本节优先级高于所有旧版视频提示词模板。它用于防止 v2/v3 中正常字段在后续生成中回退、压缩或漏写。

1. [要求] 段固定格式：每个最终视频提示词的 [要求] 第一句必须写“@<场景方向资产名>为背景保持<方向>机位”，再紧接固定句“严格遵守180度轴线与视线匹配原则，严防越轴跳切。画面干净又高级；画面里前中远景递进关系分明。极具影视写实感与物理细节真实感。”例如：“@江家客厅-夜晚正面为背景保持正面机位，严格遵守180度轴线与视线匹配原则……”。不得只在 [环境光影] 或 [人物站位] 中写场景方向后省略此句。
2. [禁令] 通用首句固定为：“视频全程严禁出现外形、着装、配饰完全相同的两个人;杜绝双胞胎或分身效果，确保同一时刻画面中该人物唯一”。随后再接当前视觉模式禁令，例如 3D 动画 CG 模式写“不得出现真人实拍感、数字人质感、真实皮肤毛孔、真人摄影、真人肖像、真实皮肤质感。”舞台定位图 / 黑白分镜图禁令仍按 v3 条件化规则执行。
3. 说出口台词格式：所有非画外音（VO）、非内心独白（OS）的人物说出口台词，必须写成“@角色 + 情绪 / 动作 / 语气 + 说：{逐字台词}”。例如“@宋知错愕地低声说：{出轨？}”。禁止只写“宋知：{出轨？}”。
4. 每个镜号必须保留“备注：<本镜号的剧情功能 / 情绪功能 / 证据点 / 衔接功能>”。备注不得省略，不得合并到动作描述中，不得只在首个镜号写。
5. 多音字 / 生僻字可读音替换优先：为保证视频原生音频或 TTS 读音正确，派发台词层允许把多音字、生僻字、易错读字替换为常用可读文字，但必须保留原始对白表，新增 dialogue_pronunciation_rewrite_map 记录 source_text、dispatch_text、rewrite_reason、priority_basis。优先级：剧本剧情描述 ＞ 文字词语用法正确性 ＞ 日常常用读音 ＞ 姓名字多用文字读音。该替换只作用于派发台词层，不得覆盖原始剧本文本。
6. 回归防护：任何后续生成若缺少 [要求] 场景机位前缀、唯一人物禁令、@角色情绪说、每镜备注、或读音替换记录，必须标记 FAIL_VIDEO_PROMPT_V4_REGRESSION，不得冻结或派发。


## 资产 v5 完整性与镜头景别优先级（最高优先级补丁）

本节同时适用于写实真人模式与3D动画CG模式。每个角色变体资产提示词必须完整展开身份锚点、角色别名、同一身份主键、三庭五眼、体型气质、服装锚点、状态变化、时代朝代职位锁、连续性禁令和负面提示；禁止只写完整继承、同一身份、继承上版等替代关键字段。后续变体必须引用原始资产图作为身份基础，但文本仍必须完整展开。

从剧本识别历史时期、朝代、年代、地域制度、职位、职务、官阶、服饰制度、器物制度，并写入 era_dynasty_lock、period_region_lock、official_rank_role_lock、costume_regulation_lock、prop_period_lock、scene_architecture_period_lock。角色、场景、道具资产提示词必须消费这些字段。

角色look_variant、场景scene_state_variant、道具prop_state_variant都必须记录before_state、after_state、change_trigger、continuity_keep、continuity_change。道具状态绑定优先，不无脑每状态出图；只有外观本体明显变化、文字证据特写风险、破损沾灰湿痕明显、剧情反转状态或读屏状态才生成独立道具资产。

同一道具在人物资产和单独道具资产中必须使用 shared_prop_visual_anchor，核心外观描述逐字一致。

分镜与视频提示词中，Skill景别规则高于剧本视觉备注。默认优先大特写、特写、近景、中景，以及前景对焦加背景高虚化。远景、全景、大远景只允许用于建立空间、人物与环境关系必须交代、战争灾害大场面或剧情强需要；否则即使剧本写全景远景，也必须改为中景以下景别。若违反，标记 FAIL_SHOT_SCALE_PRIORITY_OVERRIDE。
